## โครงสร้าง `YC_Stock_Tracker.xlsx` (5 ชีต)

```
📝 กรอกข้อมูล ─(รัน banthuek.py DD/MM/YYYY BRANCH)─▶ บันทึกสต็อครายวัน ─(copy/paste values)─▶ ฐานข้อมูลสะสม
(ฟอร์มพนักงาน 1 สาขา/วัน)                          (ฐานข้อมูลจริง ~8,700 แถว)              (คลังวิเคราะห์ + Variance + Par)
บันทึกยอดขาย = ยอดขายรายวันแยกช่องทาง (เงินสด/QR/EDC → In-store · Grab/Lineman → Delivery)
คู่มือการใช้งาน = วิธีใช้ + รายการชื่อที่ต้องยืนยัน
```

**หน่วยคู่ (แพ็ค + ชิ้น/กรัม) และสูตรคำนวณ**
- คงเหลือชิ้น: `I = ยกมา(D) + รับเข้า(F) − ขาย/ใช้(H)`
- คงเหลือกรัม: `J = MAX(ยกมา(E) + รับเข้า(G) − ใช้(H), 0)`
- Variance (ตรวจความถูกต้อง): `ยกมา + รับเข้า − ขาย − ส่งคืน − คงเหลือ` → เขียว=ตรง / แดง=ต้องตรวจ
- "ยกมาวันนี้" = "คงเหลือวันก่อนหน้า" (carry-forward อัตโนมัติ)

## `banthuek.py` ทำอะไร (7 ขั้น)
1. อ่านฟอร์ม — เอาเฉพาะเลขที่คนพิมพ์เอง (ข้ามช่องสูตร)
2. หา KEY `วันที่|สาขา|รายการ` ในฐานข้อมูล
3. Upsert (มี→update / ไม่มี→insert + carry-forward ยกมาจากวันล่าสุด)
4. คืนสูตร INDEX-MATCH ลงฟอร์ม + ล็อกช่องห้ามแก้ (สีเทา)
5. เลื่อนวันที่ (B2) ไปวันถัดไป
6. Re-save ผ่าน LibreOffice กัน xlsx พังบน Excel Mac
7. ซ่อมสูตร SUMIFS ชีตยอดขายที่ LibreOffice ลบทิ้ง (แก้ระดับ XML)

## 🚩 ข้อสังเกต/ความเสี่ยง (สำคัญตอนสร้าง App)
1. **Path ในสคริปต์ชี้ไป sandbox** (`/sessions/cool-pensive-turing/mnt/...`) — รันบนเครื่องนี้ตรง ๆ ไม่ได้ ต้องแก้ path
2. **คู่มือ vs การใช้จริงไม่ตรงกัน** — คู่มือบอกกรอกที่ `บันทึกสต็อครายวัน` แต่ระบบจริงกรอกที่ `📝 กรอกข้อมูล`
3. **ยังมี manual step** — copy → Paste Values ไปชีตสะสม ทำมือ (App ควรตัดทิ้ง)
4. **ชื่อรายการยังไม่นิ่ง** — เช่น 'ปีโป้'/'ปีโป้ลิ้นจี่', Drink บางรายการ ต้องยืนยันกับแพร
5. **BOM/Par เป็นบล็อกแนวนอน** — normalize เป็นตาราง data ก่อนใช้จริง
6. **ต้องรีเซ็ตชื่อสาขาให้ตรง** — คู่มือระบุ "Sinthom" แต่ Par/ฟอร์มใช้ SND/NVP

## จุดสำคัญเชิงธุรกิจ (เพิ่มจากแพร 2026-07-15)
- **Par Stock = ยอด reserve ขั้นต่ำต่อสาขา** ที่ต้องมีหลังเติมของทุกครั้ง
- **เติมของสัปดาห์ละ 2 ครั้ง: ทุกวันพุธ + เสาร์** → แต่ละรอบต้องเติมให้สต็อกกลับมา ≥ Par
- **ฟอร์มกรอกสต็อกสิ้นวัน** ให้พนักงานกรอกผ่าน **iPad/มือถือ** → ต้องออกแบบ mobile-responsive
